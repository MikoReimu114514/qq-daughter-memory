# qq-daughter-memory

> 给长期在线的 QQ AI 角色用的**分桶 + 权重打分 + 关联式长期记忆**。
>
> 一套工程化记忆系统：对话静默 30 分钟后打包提炼、按实体/事件/概念分桶、权重打分（重要度 × 频率 × 关联 × 时间衰减）、core 程序记忆（永久固定注入）、软淘汰（冷存储可恢复）、检索注入替代全量注入。

## 为什么

长期在线的 QQ AI 角色会面临三个问题：

1. **全量注入**：所有长期记忆拼进 system prompt，一多就挤占上下文、稀释注意力。
2. **压缩污染**：历史溢出时把旧对话原文截断拼成「早期对话」塞进记忆列表，真事实被聊天残渣淹没（实测 94 条里 84 条是残渣）。
3. **只增不减**：没有「什么该忘」的机制。

本仓库是这三个问题的工程解法，附完整实测数据与模拟脚本。

## 特性

- **对话单元打包**：静默 30 分钟 → 一次 LLM 提炼（结构化 JSON：`{text, bucket, importance, entities, links}`）
- **分桶存储**：实体 50 / 事件 80 / 概念 60（硬截断）
- **权重打分**：`60 × (importance/5) × (1+hits×0.1) × (1+links×0.15) × 衰减 × 孤立惩罚`
- **关联图**：具体实体为锚点，模型 links + 实体名自动匹配**双通道建边**；宽泛实体降级为标签
- **core 程序记忆**：重要度≥8 且（关于用户 / 被关联≥2 次 / 配置类）→ 永久区，固定注入，上限 20
- **软淘汰**：<30 进冷存储（可恢复）、30~50 压缩、≥50 保留；单日删除 ≤20%
- **检索注入**：core 全量 + 桶内关键词/实体匹配 topN

## v2.0 新增（2026-10-26）

| 能力 | 说明 |
|---|---|
| **桶溢出进冷存储** | 桶满时被截断的条目进 `cold`（不丢失）；超长对话按 20 条分块提炼，单次提炼条数动态化（8~20） |
| **冷存储激活** | 检索兜底（三桶不够时补 cold）+ 关联复活（新记忆共享实体 → cold 条目回桶）+ 显式回忆（「翻旧账/记得吗」）+ cold 二级淘汰（60 天 + 低权重） |
| **超级节点自动检测** | 不再硬编码黑名单：度数 ≥ max(5, 总量×15%) + 频率 ≥ 20% + 平均权重低 → 自动降级为标签；用户实体豁免；每轮自动重扫（含冷存储历史） |
| **core 竞争上岗** | core 满 20 时，新记忆权重高于最低分则**替换**（最低分降回桶，不丢）；核心记忆**豁免时间衰减**（程序性记忆不会因久远而遗忘） |
| **主动消息防污染** | proactive 消息带 `synthetic` 标记，打包时过滤；连续主动消息不阻塞打包（2 小时强制打包） |

**验证**：16/16 单测通过 + 60 轮迭代演化稳定（core 20 封顶、种子不丢、cold 300 封顶、泛词自动识别、无失衡）。
## v2.1 / v2.2 新增（2026-10-27）

| 能力 | 说明 |
|---|---|
| **矛盾失效** | 新记忆推翻旧记忆 → 旧记忆标 `supersededBy`/`validUntil`，检索只给「当前有效」，历史可查 |
| **最近活跃度** | `lastHitAt` + recencyFactor（7 天 1.3 / 30 天 0.8）；decay 按最近活跃——**话题回归时旧记忆能重新热起来** |
| **保胎层** | 曾主节点的关键记忆保护 6 个月（度数≥15，或≥5 且平均权重≥80），上限 30 条、竞争上岗、期满解除 |
| **双通道复活** | 实体 + 文本 2-gram 重叠（≥3）复活冷存储，另附别名表 |
| **排序回归** | 复活限量：按「实体命中 + 重叠度 + 权重」排序，每轮最多复活 12 条，剩余留冷存储 |
| **冷存储压缩** | 溢出时循环压缩（每批 30 条 → 1 条摘要），绝不 slice 丢弃 |
| **core 竞争上岗 + 永久身份** | 满 20 竞争替换、最低分降回桶；身份/规则类 `permanent` 不被挤掉；核心记忆不衰减 |
| **两阶段提炼** | 第一轮骨架标定 → 第二轮按原文细化 event 情景（80-200 字，保留对话/情绪/场景） |

**真实数据实测**（169 篇日记，别的平台 agent 数据）：v3 两阶段 57/57 事件细化成功；时间轴保胎 3→12 随时间增长；迭代 12 轮后话题回归 → 冷存储 61 条复活、总量 9→73、保胎恢复。
## 基准测试（2026-10-28）

五项基准，脚本在 `tools/benchmark-*.js`，原始数据在 `docs/benchmarks/`：

| 基准 | 结果 | 对照 |
|---|---|---|
| **检索** | Recall@12 **0.419** / MRR **0.631** / Precision 0.172 | 最近12条基线 0.080/0.081、随机 0.042/0.097（**5-8 倍**） |
| **遗忘/保胎留存** | 保胎 30 轮漂移后活跃 **12 条** vs 无保胎 **5 条**；核心留存 **0.95**；复活 12 条 | 无保胎对照组 |
| **压缩后** | 关键事实 Recall **Δ0.000**（压缩不伤记忆） | 压缩前基线 |
| **提炼** | 精确 **100%** / 召回 **75%**（F1 0.857，称呼规则补后） | 人工标注 8 条期望事实 |
| **成本** | 注入 **~1148 tokens/次**（全量的 17%，**省 83%**）；检索 1.5ms、prune 42ms；**≈0.23 元/天** | 全量注入 6794 tokens/次 |

**关键结论**：IDF 检索加权是最大改进（Recall 0.25→0.42）；保胎在 6 个月保护期内有效；压缩不伤关键记忆；提炼精确率高、称呼类已补；日成本极低。
## 实测结论（94 条真实记忆 + 90 天模拟）

| 发现 | 描述 |
|---|---|
| ✅ 权重是主淘汰轴 | 纯分桶+打分清掉 42/94 条寒暄垃圾，保留全部真事实 |
| ✅ core 隔离有效 | 身份/称呼/手册类记忆零损失 |
| ✅ 低损剪枝 | 90 天模拟总量稳定 100~120、权重不塌缩 |
| ⚠️ 六度距离做淘汰失效 | 真实记忆图孤立率 25%~82%，距离区分度低——六度只能标孤立点 |
| ⚠️ 两个陷阱 | ①宽泛实体（管理员/用户名）当超级节点会连坏全图；②用户本人不能被当宽泛噪音 |

完整分析见 [`docs/技术报告.md`](docs/技术报告.md)。

## 快速开始

> 脚本里的路径（`C:/Users/...`）需要换成你自己的 bridge 目录。

```js
const memoryV2 = require('./src/memory-v2.js');

// 加记忆（通常来自 LLM 提炼）
memoryV2.add('u123', [
  { text: '对方叫博麗ユキ，是部署我的人', bucket: 'concept', importance: 9, entities: ['管理员'] },
], { source: 'condense' });

// 检索注入
const prompt = memoryV2.formatForPrompt('u123', '你还记得我叫什么吗');

// 淘汰
memoryV2.prune('u123');
```

## 已知局限

- 记忆系统本质是有损压缩 + 启发式关联，**没有完备解**；本设计以「可恢复」（软删除/冷存储/快照）兜底。
- 六度距离只用于标孤立点，不是主淘汰轴。
- 提炼质量决定系统上限（LLM 提炼的孤立率显著低于规则模拟）。
- 未做 LongMemEval 等公开 benchmark 对照。
