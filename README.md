# qq-daughter-memory

> 给长期在线的 QQ AI 角色用的**分桶 + 权重打分 + 关联式长期记忆**。
>
> 一套工程化记忆系统：对话静默 30 分钟后打包提炼、按实体/事件/概念分桶、权重打分（重要度 × 频率 × 关联 × 时间衰减）、core 程序记忆（永久固定注入）、软淘汰（冷存储可恢复）、检索注入替代全量注入。

## 为什么

长期在线的 QQ AI 角色会面临三个问题：

1. **全量注入**：所有长期记忆拼进 system prompt，一多就挤占上下文、稀释注意力。
2. **压缩污染**：历史溢出时把旧对话原文截断拼成「早期对话」塞进记忆列表，真事实被聊天残渣淹没（实测 94 条里 84 条是残渣）。
3. **只增不减**：没有「什么该忘」的机制。

本仓库是这三个问题的工程解法，附完整实测数据与模拟脚本。

## 特性

- **对话单元打包**：静默 30 分钟 → 一次 LLM 提炼（结构化 JSON：`{text, bucket, importance, entities, links}`）
- **分桶存储**：实体 50 / 事件 80 / 概念 60（硬截断）
- **权重打分**：`60 × (importance/5) × (1+hits×0.1) × (1+links×0.15) × 衰减 × 孤立惩罚`
- **关联图**：具体实体为锚点，模型 links + 实体名自动匹配**双通道建边**；宽泛实体降级为标签
- **core 程序记忆**：重要度≥8 且（关于用户 / 被关联≥2 次 / 配置类）→ 永久区，固定注入，上限 20
- **软淘汰**：<30 进冷存储（可恢复）、30~50 压缩、≥50 保留；单日删除 ≤20%
- **检索注入**：core 全量 + 桶内关键词/实体匹配 topN

## 实测结论（94 条真实记忆 + 90 天模拟）

| 发现 | 描述 |
|---|---|
| ✅ 权重是主淘汰轴 | 纯分桶+打分清掉 42/94 条寒暄垃圾，保留全部真事实 |
| ✅ core 隔离有效 | 身份/称呼/手册类记忆零损失 |
| ✅ 低损剪枝 | 90 天模拟总量稳定 100~120、权重不塌缩 |
| ⚠️ 六度距离做淘汰失效 | 真实记忆图孤立率 25%~82%，距离区分度低——六度只能标孤立点 |
| ⚠️ 两个陷阱 | ①宽泛实体（管理员/用户名）当超级节点会连坏全图；②用户本人不能被当宽泛噪音 |

完整分析见 [`docs/技术报告.md`](docs/技术报告.md)。

## 快速开始

> 脚本里的路径（`C:/Users/...`）需要换成你自己的 bridge 目录。

```js
const memoryV2 = require('./src/memory-v2.js');

// 加记忆（通常来自 LLM 提炼）
memoryV2.add('u123', [
  { text: '对方叫博麗ユキ，是部署我的人', bucket: 'concept', importance: 9, entities: ['管理员'] },
], { source: 'condense' });

// 检索注入
const prompt = memoryV2.formatForPrompt('u123', '你还记得我叫什么吗');

// 淘汰
memoryV2.prune('u123');
```

## 已知局限

- 记忆系统本质是有损压缩 + 启发式关联，**没有完备解**；本设计以「可恢复」（软删除/冷存储/快照）兜底。
- 六度距离只用于标孤立点，不是主淘汰轴。
- 提炼质量决定系统上限（LLM 提炼的孤立率显著低于规则模拟）。
- 未做 LongMemEval 等公开 benchmark 对照。
